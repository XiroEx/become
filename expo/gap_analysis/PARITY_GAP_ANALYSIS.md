# Native parity gap analysis: `expo/` against the web app

**Baseline:** commit `82f8b4bc` (origin/beta, whose tree is identical to origin/main, which is production), audited 2026-09-28. Written 2026-09-29.

**Scope:** every surface of the Next.js web app (`webapp/`, the source of truth) compared with the React Native app (`expo/`, Expo SDK 56, expo-router, NativeWind 4) and the zod client only the native app consumes (`shared/api-client`). The result is 206 tickets (122 for the first store release) under EPIC Native App Parity (board card 6ab027beee5866d95d14dea5), keyed NP-001 to NP-206. This document supersedes `expo/gap_analysis/GAPS.md`.

**Decisions it honours:** redbtn publishes the apps (9/13). No In-App Purchase: Plus is sold only by external link to the web checkout on the US storefront, and prices always come from the API (9/20, Apple 3.1.1(a)). Jon archived the iOS wrapper feature on 9/27, and on 9/28 George decided the native app ships on both stores, replacing the planned iOS wrapper and the Android Trusted Web Activity alike, so it is the first binary on both listings. (The slice analysis ran before that decision and treated Android v1 as the TWA; the plan, the waves and this document were corrected for it on 9/29.) Chat and community are on hold for the first store release (9/28), so the native v1 hides them.

**On the board:** every NP key is a ticket under [EPIC: Native App Parity](https://board.redbtn.io/b/6a70c4ea2fff468f8e253a89?card=6ab027beee5866d95d14dea5) on the Become redBoard (written 2026-09-29); the ticket index at the end links each one. Keys NP-205 and NP-206 and the Android release in NP-201 were added after the slice analysis, for the 9/28 decision to ship the native app on both stores.

## 1. How this was produced

- **Three slices, one owner each.** Slice A covered the platform, account, push, native-only capabilities and release; slice B training, the dashboard, streaks, the calendar and progress; slice C nutrition, Mind, community and chat, admin and AI. Each analyst read the current web app at `82f8b4bc` (not the May plan), the matching `expo/` and `shared/api-client` code, the board's Native App Parity and App & Play Store Readiness trees, and the 2026-07-14 state-of-play report, and cited `path:line` for every claim.
- **Every "native lacks X" claim is backed by a grep of `expo/` and `shared/` that finds nothing.** The greps that carry the headline gaps, all over `expo/app`, `expo/components`, `expo/lib` and `shared/api-client/src` unless noted, and all with zero hits: `expo-camera|CameraView|BarCodeScanner|barcode`; `expo-image-picker|ImagePicker|launchCamera`; `speech|Speech|MirrorScene`; `Haptics|expo-haptics|Vibration|Share.share`; `/api/ai/|runAiTask|allowanceTicket|EntitlementRequired`; `ai-consent|aiConsent|AI_CONSENT`; `entitlement|Entitlement|gateFrom|UpgradeSheet|TierGate|requiresTier`; `/api/mind/|SessionPlayer|mindXP|composeSession` (only the tz prefix list matches); `/api/report|/api/block|blockedUsers`; `<Link` (no link component anywhere); `AppState`; `expo-font|useFonts|fontFamily`; `sentry|bugsnag` (also over `webapp/`); and `expo-notifications`, `expo-dev-client` and `expo-updates` in `expo/package.json`.
- **A verifier re-checked each slice.** It re-ran the commands, checked that every cited path exists and every cited line range is inside its file (216 paths in slice A alone), read the cited behaviour, corrected wrong premises (for example: plans do auto-promote on the web; windowed allowances key on the stored timezone, not the request's; the onboarding finish writes `PUT /api/goals`; beta shares production's database), split tickets bigger than about three days, and added gaps the first pass missed, including the Metro bundling failure.
- **This synthesis merged the three verified slices.** Overlaps got one owner (the timezone fix, the web-path resolver, the signed-in web hand-off, the logic-sharing decision, the chat flag, the refusal classifier); every dependency points at a ticket key or a board card; the graph is acyclic, no ticket depends on a later wave, and no v1 ticket depends on a non-v1 ticket. A completeness pass added eight tickets no slice owned: the day rollover on return to the foreground (NP-035), recording the member's timezone when an app opens (NP-070), four training product decisions (NP-028), a web sharing hole (NP-029), App Store screenshots from the native build (NP-119), the offline live workout (NP-191), the web's typeface (NP-160), and last-known data with offline and error states (NP-036). Six new stories hold work no existing story fitted: crash reporting, OTA updates and the version gate (NS-01); theme, typeface and accessibility (NS-02); onboarding (NS-03); the food log on MealLog (NS-04); the calendar (NS-05); and the live workout (NS-06), split out of the training audit story, which had about 25 tickets. Keys run in order of wave, then priority, then the story order of the board tree, with new stories after their feature's existing ones.
- **Read-only.** No commits, pushes, board writes, messages or deploys, and no production data. The only commands run were `npm ci`, `tsc`, ESLint, Jest, `expo install --check`, expo-doctor and a Metro export, inside the worktree's `expo/` and `shared/api-client` or an isolated copy of them.

## 2. Headline findings

1. **The native app cannot be built or launched as it stands, although its tests are green.** Metro cannot resolve `@become/api-client`, so no bundle of any kind can be produced; React 19.2.6 against React Native 0.85.3's 19.2.3 renderer makes the real root layout throw on import; expo-doctor reports a Hermes memory regression fixed only on SDK 57; `expo/assets/` and the EAS project do not exist. Jest passes 620 tests because no test renders the real layouts or bundles the app. (NP-004, NP-006, NP-005, NP-014, NP-007, NP-008)
2. **Every native date is the UTC day.** The shared client sends `tz` as an IANA zone name, the server reads minutes west of UTC and turns anything else into 0, and native writes carry no `tz` at all, so a mood logged at 9 pm in New York lands on tomorrow and native workout saves never record the member's zone. (NP-009)
3. **The launch path loses the session and the tab bar is unusable.** In-memory token stores send every launch, and every cold start from a sign-in or restore link, to `/login`; `useAuth` drops the token on a network error and never stores the refreshed one; the tab bar renders 20 slots; the Health toggle writes over the session token. (NP-002, NP-003, NP-001)
4. **Four native paths write wrong data as soon as they are reachable,** and beta shares production's database, so pointing a test build at beta is no protection: food logging sends every USDA food through the quota-gated custom-food create (which 500s today and would spend free members' slots) and scales per-serving nutrition as per 100 g; a swap files the replacement's sets and PRs under the original exercise; schedule settings regenerate the remaining program into the past; enrolment stores no start date and creates no schedule. The Settings weight box also stores a kilogram member's value as kilograms while labelling it pounds. (NP-011, NP-083, NP-069, NP-074, NP-048)
5. **The account and money layer is missing while the paywall is on in production.** Native sign-ups get no Terms agreement on record (there is no consent gate), there is no AI consent, no entitlements store, upgrade sheet or plan page, no API serves prices, and a purchase started in the app returns the buyer to a signed-out Safari page. (NP-045, NP-046, NP-049, NP-052, NP-050, NP-053, NP-051, NP-054)
6. **Push is shells on both ends.** `expo-notifications` is not installed, registration posts to a route that does not exist, the tap router switches on categories the server never sends, and the server's send path skips native devices. Members with no stored timezone (only workout saves record one) get no reminders on either client. (NP-030, NP-063, NP-064, NP-065, NP-066, NP-067, NP-068, NP-070)
7. **The headline features are absent natively:** no camera (barcode scan, meal photo estimate), no AI client (so no allowance ticket, consent or spend-cap handling), and Mind is a mood picker where the web runs a 50-session path with scenes, speech, the mirror camera, XP and chapters. Mind has the worst relative gap and the longest chain in the plan. (NP-059, NP-088, NP-089, NP-090, NP-038, NP-097, NP-098, NP-103, NP-099, NP-100, NP-101)
8. **The shared client is a one-sided contract.** Its schemas describe the May API (speculative shapes no route returns, recipes read `nutrition` where the web stores `totalsPerServing`), there are no schemas for account, entitlements, dashboard, progress, Mind or AI, and nothing fails when the web changes a response: about 680 web commits have landed since 2026-05-31 against 4 in `expo/` and `shared/`. (NP-015, NP-016 plus one ticket per domain)
9. **The audit found web bugs that hurt web members today:** workout saves credit an older missed schedule slot instead of today's for members west of UTC (NP-027); the Mind home drops a session begun in a US evening because Begin sends `tzOffset` while the route reads `tz` (NP-031); a completing workout save retried after midnight logs a second workout (NP-139); `POST /api/share` publishes another member's custom program by id (NP-029); the dashboard nutrition card's Quick add link is read by nothing (NP-149). Separately, the store deletion feature is marked done with session revocation ticked, but `verifyAuth` never reads the user row (open question).
10. **Chat is live natively and hidden on the web.** Native gives every member a Chat tab that polls every 30 seconds, while the web shows chat, community, groups and events as admin-only "Coming soon". The v1 build hides them behind one flag (NP-032); report and block wait for the web.
11. **Much of the web is not a gap.** The Journal, Meditation and Sleep tabs, MindHub, VisionTab, `/api/ai/mind/generate` and `/api/ai/nutrition/product` have no live web caller; `/dashboard/insights/[metricId]` is a placeholder; `/dashboard/customize` is legacy. None of them is ported. No surface is at parity today: of the 180 matrix rows, 30 are Broken, 28 Partial, 98 Missing and 24 Web-only.
12. **The size of the job.** With the native app on both stores, v1 is 122 tickets, about 192 engineer-days. The critical path to submission is 12 tickets and 28 working days, then one to two weeks of App Review, and it cannot start until the Apple Team ID and App Store Connect record exist (store story 6ab0281d); the Play release also needs the Play Console record with App Signing (6ab02822).

1. **The critical path starts with people, not code.** The Apple Team ID and App Store Connect record (6ab0281d), the Play Console record (6ab02822), the reviewer demo login's server route (6ab02884), Manage billing on the web (6ab189bb), the push credentials (NP-063) and the processor list in the Privacy Policy (6ab028bd) are all To do or in progress outside this epic.
2. **The web ships daily** (about 680 commits since 2026-05-31 against 4 native). Until the contract test (NP-016) lands, any web change can break the native app silently; copied pure logic drifts unless the lockstep tests (NP-017 decides the mechanism) run in the web's CI.
3. **Green tests are not a working app.** 620 passing tests coexist with an app that cannot bundle, 20 test-only modules and inert push, health, biometrics and offline code. Every wave ends in a device demo for this reason.
4. **Beta shares production's database.** A development or preview build pointed at beta writes real member data. Until NP-011, NP-083, NP-074, NP-069 land, builds that reach those paths are used only with named test accounts.
5. **The timezone contract** (NP-009) must land before anyone uses a native build: until then every native write lands on the UTC day and native workout saves record no zone, which also keys reminders and allowance windows.
6. **Sessions are not revoked server-side.** `verifyAuth` (`webapp/lib/auth.ts:132-165`) never reads the user row, so native sign-out and deletion must leave nothing on the device (NP-047), and a token on another device keeps working (open question).
7. **External purchase rules are narrow.** Selling by link is allowed only on the US storefront, availability must be US-only, and the rule has changed twice in two years. A same-domain universal link tapped in Safari stays in Safari, so the return from checkout needs the `become://` scheme or a link on the other domain (NP-051).
8. **Native modules need development builds.** Camera, speech, HealthKit, widgets and Live Activities cannot be tested in Expo Go; the first device build (NP-008) gates most of wave 2.
9. **The allowance-ticket rule is easy to break silently.** A native photo estimate that drops the follow-up ticket makes a free member's first correction cost tomorrow's scan (NP-090).
10. **Moving web targets** (section 9): porting before the trial, the tutorial decline, Manage billing, the cardio layout, the summary metrics or The Becoming settle means porting twice.
11. **Dark-only v1** (NP-013) may not be what Jon expects; light mode is NP-123, 33 files.
12. **The chat API has no role gate**, and every chat message pushes to `/dashboard/chat`. Hiding chat natively (NP-032) does not make the API safe.
13. **The live-workout draft sits in the secure store**, which warns above 2 KB per value; a long workout's draft can fail to save until NP-079 moves it.
14. **The v1 scope is large:** 122 tickets. If the date matters more than parity, the P2 v1 tickets are the first to move after the release (open questions).
15. **SDK cadence.** After the move to SDK 57, plan an SDK upgrade every half year, or EAS build images stop supporting the app.
